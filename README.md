# Neowise: AI-помощник для входящих заявок

Менеджер вводит текст заявки, получает тему и черновик ответа, проверяет его и сам решает, что отправить клиенту. При сбое AI страница предлагает ручной разбор и удаляет предыдущий черновик. Используются только учебные данные и локальный имитатор AI.

## Запуск

Нужен Node.js 20 или новее. Зависимостей, установки пакетов и API-ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Остановить сервер: `Ctrl+C`. Другой порт:

```sh
PORT=3001 node server.mjs
```

## Тесты

В отдельном терминале из корня проекта:

```sh
node --test
```

Тесты используют встроенные модули Node.js. HTTP-тесты сами запускают и останавливают сервер на свободном локальном порту; отдельно запускать приложение не требуется. Проверяются корректные темы, некорректный ввод, все пять сбоев имитатора, ограничение ожидания, восстановление после ошибки и очистка прежнего черновика в интерфейсе.

Проверка синтаксиса серверных модулей:

```sh
node --check server.mjs
node --check triage.mjs
node --check mock-ai.mjs
```

## Контракт API

`POST /api/triage`, `Content-Type: application/json`, тело: `{"text":"Сколько стоит доставка?"}`.

| Ситуация | HTTP | Ответ |
| --- | --- | --- |
| Пустой или пробельный текст, отсутствующее поле, неверный тип, неверный JSON | 400 | `{"status":"invalid_input"}` |
| Проверенный ответ AI | 200 | `{"status":"ready","topic":"pricing","draft":"Спасибо за обращение. Уточним детали заявки."}` |
| Таймаут, ошибка AI, неверный JSON или неподходящие поля ответа AI | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

Допустимые темы: `delivery`, `pricing`, `other`. Черновик должен быть строкой с хотя бы одним непробельным символом. Сервис возвращает только предусмотренные контрактом поля. Если в тексте есть и доставка, и цена, выданный имитатор выбирает `pricing`; его поведение сохранено.

Для проверки ошибок введите на странице любую из меток: `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Например, сначала разберите «Когда доставка?», затем `[timeout]`: старый черновик должен исчезнуть, а сообщение — предложить ручной разбор.

Проверка API при работающем сервере:

```sh
curl -i http://127.0.0.1:3000/api/triage \
  -H 'Content-Type: application/json' \
  -d '{"text":"[timeout]"}'

curl -i http://127.0.0.1:3000/api/triage \
  -H 'Content-Type: application/json' \
  -d '{"text":"   "}'
```

Первый запрос вернёт `manual_review`, второй — HTTP 400 и `invalid_input`.

## Решение и ответы для проверки

**Где проверяется результат AI?** В `triage.mjs`, после вызова модели и разбора JSON: проверяются объект ответа, допустимая тема и непустой строковый черновик. Недостаточно получить от модели синтаксически корректный JSON. Сервер отдельно проверяет пользовательский ввод до обращения к AI.

**Что происходит при сбое?** Ожидание имитатора ограничено 300 мс через `AbortSignal.timeout(300)`. Сигнал передаётся в существующий `classify`, который поддерживает отмену. Таймаут, исключение и неподходящий результат превращаются в `manual_review` с `null` в обоих полях. Страница очищает тему и черновик ещё перед новым запросом, скрывает панель и при сбое предлагает ручной разбор. Ошибка сети или неожиданный ответ API обрабатываются так же. Во время запроса повторная отправка заблокирована.

**Почему при сбое AI HTTP 200?** По условию ручной разбор — предусмотренный результат обработки корректной заявки. Неверный пользовательский ввод получает HTTP 400. Статус `manual_review` явно сообщает интерфейсу, что автоматического результата нет.

**Какой AI использован?** Для реализации, тестов и проверки решения использован OpenAI Codex. Само приложение не обращается к внешним AI-сервисам: используется выданный `mock-ai.mjs` без изменений.

**Что проверено исполняемыми проверками?** `node --test`: 32 теста прошли. HTTP-тесты обращаются к реальному локальному серверу и выданному имитатору. Тесты интерфейса выполняют настоящий скрипт страницы с минимальным DOM-окружением и проверяют смену состояний. При подготовке решения дополнительно выполнена разовая проверка в headless Chrome: реальный запуск `node server.mjs` и шесть переходов от успешного результата к каждой из пяти ошибок и пустому вводу. Визуальная вёрстка и работа браузерных средств доступности вручную не проверялись. Команды воспроизводимого набора тестов и проверки синтаксиса приведены выше.

**Как исключено выполнение текста AI как HTML?** Тема и черновик выводятся через `textContent`, без `innerHTML`. Ответ клиенту автоматически не отправляется.

**Польза менеджеру и измерение.** Помощник сокращает время подготовки ответа и при сбое явно передаёт заявку на ручной разбор, убирая прежний черновик; эффект можно измерить медианным временем обработки заявки до и после внедрения, отдельно учитывая долю ручных разборов.

Начальные исходники сохранены первым коммитом в `main`, решение подготовлено в отдельной ветке для PR.
